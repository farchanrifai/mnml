## Implemented fixes

| Area | Problem and resulting behavior | Evidence |
|---|---|---|
| Tab lifecycle | Every prepared tab left address/title subscriptions in its previous window's lifetime bag. Subscriptions now belong to the tab, are replaced when ownership moves, and are cancelled on close. This removes growing stale subscriptions and old-window callbacks. | `Browser.prepare`, `Tab.ownerWatch`, `Tab.close`; 20 repeated owner changes and closed-tab history behavior tested. |
| Session restoration | Appending each restored tab published a growing row and repeatedly scanned it for MRU reconciliation. Restore now publishes the assembled row while preserving saved order, legacy split relationships, pins, and lazy background pages. | `Browser.restoreSession`; 200 restored entries test checks ordering, legacy pairing, bounded publications, and no built background pages. |
| Window resources | A discarded Browser left its sleep timer and memory-pressure source alive. Teardown now invalidates/cancels them. | `Browser.deinit`; release and timer invalidation tested. |
| Downloads | Each progress poll published three fields even when their values had not changed. Only changed values publish now. | `FetchEntry.record`; repeated identical progress produces zero view updates. |
| Stage updates | SwiftUI updates recreated the displayed page's fullscreen observation. The stage reuses the observation while the page stays the same and releases it on replacement or an empty stage. | `StageView.show`; observation identity and deallocation tested. This changes app subscription ownership, not the engine. |
| MRU preference | The same switch had two identical subscriptions clearing the preview cache. | Duplicate subscription removed; existing switcher coverage retained. |
| Hover preview | A sleeping-tab preview could finish after hovering a different row; checking the current pending item allowed an old picture through. Each request now has a generation, checked before decoding and again at delivery alongside current URL, ownership, selection, and edit state. | `TabPreview`; deterministic A → B → A, navigation, selection, rename, removal, and hide regression. |
| Address completion | AppKit selection ranges use UTF-16 offsets; Swift character counts selected the wrong suffix for emoji and combining accents. | Shared `AddressField.Coordinator.select` and all callers corrected; Unicode suffix selection tested. |
| Focus | Queued page/address focus callbacks could execute after a new field or panel appeared. Callbacks now recheck current visibility/request state; shared modal guards include import, release notes, What's New, and shortcut questions. | `ContentView.handBack`, `nothingOver`, `AddressField.updateNSView`; new-field and Settings race plus successful focus return tested. |
| Settings controls | Gesture-only switches and segmented choices lacked keyboard/assistive behavior. At the user's request, their original custom appearance is restored, using plain Buttons for activation and native Toggle/Picker accessibility representations with contextual labels. | Shared `Switch`, `Segmented`, and `Line`, plus direct callers. Native keyboard/VoiceOver behavior still needs live confirmation. |
| Actions and labels | Password actions existed only on hover. They remain visible; safe leaf rows in suggestions, bookmarks, import, password expansion, and split selection are real Buttons. Search fields, navigation icons, zoom controls, Send/Stop, and spaces have labels; attachments have a named removal action. | Existing actions, authentication, and persistence retained. Nested rows with separate actions/drag behavior are in the next phase. |
| Panel fit | Fixed Settings and Archive sizes exceeded the supported 640 × 420 window. Shared panels now accept smaller proposals with margins; the shortcut list can narrow. | Settings, Plate, ArchivePanel, ShortcutsPage. Minimum-window and long-content screenshots remain an acceptance gate. |
| Reduce Motion | Several raw springs/eases, field glow, chat pacing/waiting dots, split dismissal, and refusal shakes bypassed the existing policy. Those paths now respect it; instant sidebar layout no longer waits through 0.45 seconds of mirror suppression. | Reuses `Motion` and SwiftUI's accessibility environment; normal-motion curves retained. Live toggling and complete gesture coverage remain to verify. |

The UI changes reuse platform interaction semantics and existing helpers while retaining the app's custom switch and segmented-control appearance. Apple documents the interaction and accessibility behavior provided by [system buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) and the need to support [accessibility preferences and labels](https://developer.apple.com/design/human-interface-guidelines/accessibility).

## Measurement recipe

Use identical Release/SDK builds, a fresh named test world, local static content, the same window size/appearance/effects, and a confirmed foreground/key/visible window for each comparison. Use 10/50/200-tab workloads, grouped tabs and multiple spaces; add 10,000 bookmarks and a 3,000-entry import fixture for the data paths. Avoid recording, allocation snapshots, and heavy tracing during the lightweight input-latency run; measure their overhead separately.

Record first usable frame (cold/warm), interaction median/p95/max, app main-thread stacks, body/layout work, animation hitch intervals at the actual refresh rate, live allocation generations after settle, timer wakeups, and file/lock waits. Proposed acceptance targets are under 100ms discrete response, no sustained main-thread hangs, and no visible interruption in motion; these are targets, not measurements from this run. Verify rapid reversal, cancellation, backgrounding, and immediate quit alongside throughput.
